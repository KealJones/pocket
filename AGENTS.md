# Working on Napkin Next

Keep `.ncon` as direct concept notation for authored knowledge and behavior. Keep
the original observation intact. Do not put word-specific sentence meanings in host
dispatch, introduce silent spell correction, drop articles, or turn retrieved text
into executable definitions. Unknown evaluation yields residuals; unknown input
creates persistent investigation work.

Separate candidates from committed readings, facts from evidence, reward from truth,
and interpretation from execution. Every derived assertion should carry the evidence
used to derive it, including type constraints and learned procedures. Retraction must
invalidate dependents while preserving observations. Scores are not probabilities.

Keep runtime responsibilities explicit in ARCHITECTURE.md; moving semantic rules
into generic-sounding host functions does not make the runtime less opinionated.
Favor mechanical primitives with readable concept programs. No teacher LLM or
opaque model should become a required component without an explicit design decision.

Use `npm test`, `npm run check`, and the demo for behavior changes. Tests should
exercise actual learning, persistence, ambiguity, failure, and revision. Do not add
hardcoded answer paths just to pass examples. Keep examples optional, and boot must
fail if required packs or executable definitions are absent. Update verification
notes honestly; mocked source tests are not live-service validation.
